For this assignment, I’d keep the stack very simple and ship it as **one Next.js app**.

| Layer | Recommendation | Why |
| --- | --- | --- |
| Frontend | **Next.js + TypeScript** | Fast to build, routing/API in one repo |
| UI | **Tailwind + shadcn/ui** | Good for reproducing Fathom quickly |
| Database | **Supabase Postgres** | Meetings, transcripts, actions, highlights, clips |
| File storage | **Supabase Storage** | Meeting audio + any generated assets |
| AI | **Gemini API** | Summaries, templates, action extraction |
| Audio | Native <audio> first | Enough for play/pause/seek/timestamps |
| Long transcript | **react-virtuoso** | Handles the 2,500+ segment one-hour transcript smoothly |
| Search | Postgres full-text search | Good enough for cross-meeting transcript search |
| Deployment | **Vercel** | Easiest deployment for Next.js |
| Validation | **Zod** | Validate AI output before saving it |

I would structure the data around these core tables:

- meetings
- transcript\_segments
- summaries
- action\_items
- highlights
- clips

For the public demo, I would **skip authentication initially**. Give each browser a generated visitor ID and keep its edits isolated. The original sample meeting data stays read-only, while edits/highlights can be stored against that visitor ID.

For AI, the flow should be:

transcript → Gemini → Zod validation → save structured result → render

That gives us stable fields such as:

TypeScript

`{ summary, keyTakeaways, actionItems: [ { task, owner, dueDate, condition, sourceTimestamp } ] }`

For playback, I would also avoid adding a waveform library initially. Native audio already gives us everything important:

TypeScript

`audio.currentTime = transcriptSegment.startTime`

So clicking 03:42 in the transcript jumps straight to 03:42 in the recording.

I **wouldn't use FastAPI, LangGraph, queues, Redis, or a separate Python backend** for this assignment. They add infrastructure without helping the main Fathom experience.

So the stack I’d actually build with is:

**Next.js + TypeScript + Tailwind + shadcn/ui + Supabase + Gemini + Zod + react-virtuoso + Vercel.**

That is enough to implement every feature in our selected scope without making the architecture bigger than the assignment.
